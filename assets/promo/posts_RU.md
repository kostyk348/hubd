# Посты для запуска hubd (RU)

## Telegram-канал (короткий)

**hubd 1.0 — хаб подписок и сканер источников без единой зависимости**

Хватит cron'ом опрашивать 40 страниц. hubd превращает «опрос» в «подписку»:
публикация идёт в **тему**, подписчики — в аренду, неподтверждённая доставка
повторяется с backoff (5с → 1ч), а когда попытки кончились — хаб честно
отвечает 503 с причиной. Тишины и потерь нет.

- сканер источников: ETag/If-Modified-Since, sha256-дедуп, 1 req/s на хост;
- адаптеры: RSS/Atom → событие на запись, JSON-API → событие на значение
  (дедуп по значению, а не по шумному телу);
- обе стороны WebSub: хаб и клиент (discover + listen);
- токены издателя, политики тем, TLS — когда нужно;
- Python 3.11+, только stdlib: pip install не нужен.

153 теста + живая демка: `python3 -m hubd demo` (11 проверок на loopback).
GitHub: github.com/kostyk348/hubd

## Хабр (лид статьи)

В дайджесте «RFC-кладбище» музея потерянных идей есть три записи, из которых
вырастает маленький, но законченный протокол: `ipmulticast` (адрес группы вместо
списка получателей), `pubsubhubbub` (pubsub поверх HTTP, ставший WebSub) и
`rsvp`/`atmip` (контракт доставки, где неподтверждённое не теряется, а честно
повторяется и в пределе отказывает). hubd — рабочая реализация этих идей на
чистом stdlib Python: хаб подписок-аренд, сканер источников с условным GET и
адаптерами лент/API, плюс клиентская сторона WebSub. В статье — почему коды
ответа публикации честные (200/202/502/503), зачем дедупликация JSON-событий
идёт по значению, а не по телу, и как выглядит очередь повторов, которая
переживает перезапуск.
