# Changelog — hubd

Все заметные изменения проекта фиксируются здесь.
Формат — упрощённый [Keep a Changelog](https://keepachangelog.com/); версии — [SemVer](https://semver.org/).

## v1.0.0 — универсальный hubd (2026-10-30)

Ядро предметно-независимо: музей — один из примеров списка наблюдения, а не требование.

### Добавлено

- **Адаптеры источников** (`adapters.py`): `plain` (тело целиком, прежнее поведение),
  `json` (значение по пути `json_path`, дедупликация по значению — шумные API без
  валидаторов перестают создавать фантомные события), `rss`/`atom`/`feed` (событие на каждую
  новую/изменённую запись, `max_entries`, `per_entry`). Первый обход — знакомство: состояние
  адаптера сеется, событий нет.
- **Слот плагинов** (`plugins.py`): `--plugins dir` — свои адаптеры (`extract`) и фильтры
  (`transform`) без правки ядра; сбоящий плагин — видимая строка, обход не роняется.
- **WebSub-клиент**: `discover` (поиск хаба по `Link`-заголовку и разметке, WebSub §4;
  `--subscribe` сразу подписывает), `listen` (сервер обратного вызова подписчика: challenge
  эхом, `hub.mode=denied`, доставки с проверкой `X-Hub-Signature` по секретам-шаблонам тем,
  JSONL-журнал), `subscribe` (прямая подписка у хаба).
- **Токены издателя** (`auth.py`): `serve --publish-tokens tokens.json` — в файле только
  sha256-хеши (открытый токен — ошибка чтения), scope по темам (fnmatch), `401` с причиной;
  генерация — `hubd token`.
- **Политики тем**: `serve --policy policy.json` — `{"allow": [...], "deny": [...]}` (fnmatch,
  deny выигрывает); `--topic-prefix` остался как сахар.
- **TLS**: `serve --tls-cert/--tls-key` — https без смены протокола.

### Изменено

- `User-Agent` сканера — `hubd/1.0 (+universal)`.
- Событие сканера нормализовано: `topic`, `url`, `payload`, `hash`, `content_type`
  (поле `status` издавалось, но не использовалось — убрано).

### Проверено

- 153 теста (`+49` новых: адаптеры, плагины, discovery, listen, auth, policy, TLS) — OK;
- `hubd demo` — 11 проверок, 0 провалено.

## v0.2.0 — очередь повторов и честные коды (2026-10-17)

- очередь неподтверждённых доставок на диске: backoff 5 с ×2 до часа, до 8 попыток,
  затем `degraded` + `503`; тела >256 КБ честно не ставятся в очередь (`502`);
- честный код публикации: `202`, когда не всё подтверждено (раньше частичная доставка
  выглядела как `200`);
- `hub.mode` в `/subscribe` проверяется; `hub.mode=denied` от подписчика → `400`;
  отказ хаба → подписчику уходит `GET hub.mode=denied&hub.reason=…` (WebSub §5.2);
- очередь кандидатов: `scan` кладёт кандидатов (дедупликация по теме/адресу/отпечатку),
  триаж ставит `--accept/--reject --reason`;
- сбор и доставка разведены: `scan --publish` — явный флаг; недоступный хаб — человеческое
  сообщение и код 0 у `scan`/`retry`/`subs`, а не traceback;
- `hubd watchlist`: 47 источников из архива музея с провенансом по `id`;
- демонстрация: 11 проверок; 104 теста.

## v0.1.0 — first snapshot (2026-10-16)

- хаб подписок: аренда с истечением и продлением, проверка намерения challenge'ом,
  доставка с `X-Hub-Signature: sha256=…`, журнал JSONL, `/healthz`, `/subscriptions`, `/journal`;
- сканер: условный GET (`If-None-Match`/`If-Modified-Since`), дедупликация по sha256,
  вежливая пауза 1 запрос/сек на хост, подавление источников без валидаторов;
- Python 3.11+, только stdlib; CI — матрица 3.11/3.12/3.13.
