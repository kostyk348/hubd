# Contributing — hubd

PR приветствуются. Несколько правил, которые делают этот репозиторий тем, что он есть.

## Дисциплина зависимостей

**Python 3.11+ и только стандартная библиотека.** `pip install` в этом репозитории не должен
появиться без очень веской причины: ноль зависимостей — это фича (хаб поднимается на любой
машине с Python, включая старые серверы без сети). Если без зависимости никак — сначала
обсудите в issue.

## Рабочий процесс

1. Форкните или ветвьтесь от `master`: `git checkout -b feat/моя-фича`.
2. Перед каждым коммитом тесты должны быть зелёными:

   ```
   python3 -m unittest discover -s tests -t .
   ```

3. «Работает» подтверждается выводом команды, а не описанием. Если не работает — пишите в
   PR, что именно не работает.
4. PR: зелёный CI (матрица Python 3.11 / 3.12 / 3.13) → merge. Изменения фиксируются в
   `CHANGELOG.md`.

## Стиль коммитов

`<область>: <что изменилось>` — сообщения на русском или английском:

```
hub: очередь повторных доставок
scan: адаптеры источников (plain/json/rss/atom)
fix: challenge не ломается на callback с query-параметрами
```

## Чего мы не делаем

- Не добавляем TLS-терминацию куда-либо, кроме `serve` (за обратным прокси это чужая работа).
- Не храним секреты подписок наружу: `/subscriptions` никогда не отдаёт `hub.secret`.
- Не превращаем «нет подписчиков» в ошибку: публикация в пустую тема — штатный `200` с note.
- Не пишем в чужие каталоги: hubd работает только со своими `--store`/`--state`/`--queue`.

## Тесты

Новая функциональность идёт в паре с тестами. Нужные сценарии уже покрыты примерами:
loopback-серверы (`test_hub.py`, `test_listen.py`, `test_tls.py`), поддельные источники
(`test_scan.py`, `test_adapters.py`), плагины из временного каталога (`test_plugins.py`).
Управляемые часы (`Clock`) — вместо `time.sleep`, где можно.

## Лицензия

Внося вклад, вы соглашаетесь, что ваш код распространяется под Apache-2.0.
